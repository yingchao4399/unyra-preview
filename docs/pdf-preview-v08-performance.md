# PDF 快速阅读预览版 0.7.6-beta.0.2：实现与验收

版本：`0.7.6-beta.0.2`。Windows x64 / Electron 44.4.5 / PDF.js 6.5.438。

## 样本与问题定位

样本为 `D:\BaiduNetdiskDownload\实验心理学  第9版_坎特威茨.pdf`，208,800,122 字节、686 页，PDF 1.3，扫描图像为主，无加密、非线性化，**没有内置目录**。测试只将文档作为数据，没有执行文档中的任何指令。

原加载链先读取整文件并转成 Base64，会产生文件字节、字符串、解码缓冲等副本。原阅读器还为大量页面维持渲染资源。除此之外，本书顶层页树直接引用 686 个页面，页面字典分布在扫描图像之间；PDF.js 6.5.438 在首屏前预取这些字典并检查末页，导致即使引入 Range，也可能在第一页显示前读取接近整本文件。

浏览器和成熟阅读器的快速显示来自按需读取、成熟的页树与图片缓存、后台解码和有限页面渲染。Kimi 等产品展示文件的时间也不等于完成全书 OCR 的时间；预览、文本解析、视觉理解和检索通常能够逐步完成。此版采用“先阅读、后台逐页解析、AI 查询已有内容”的流程，未对任何云端产品做速度对比实测。

## 已实现

### 读取与引擎

- `unyra-pdf://` URL 不暴露路径，使用随机会话令牌。主进程校验本地 PDF 路径和文件头，支持 GET/HEAD/Range、200/206/416，拒绝无令牌和越权 URL。读取使用文件流，文件变化后要求重开。
- PDF.js 的内置 URL Range 仅对 HTTP(S) 启用，因此自定义 Electron 协议通过 `PDFDataRangeTransport` 显式请求字节范围。首块 1 MiB，后续块 64 KiB；校验 206、Content-Range 和返回长度。
- `disableStream: true`、`disableAutoFetch: true`，由阅读与 OCR 显式请求需要的数据。与原计划参数不同，这是防止后台自动读完整本文件所必需的调整。
- 固定版本 worker 补丁移除顶层页字典的全量预取，并延迟正常加载时的末页校验；远跳最多前瞻 64 个页树节点以重叠 I/O。保留 PDF.js 原始子树计数与损坏文档恢复路径，不根据 Count 与 Kids 长度相等就假设页树扁平。匹配不到精确补丁时明确报错。
- 协议启动失败仍可使用旧 Base64 逻辑回退。正常大文件路径的验收禁止调用该逻辑；文档已打开后分段读取失败会销毁会话并提示重开。

### 页面与跳转

- 全书保留轻量占位，只有可见页及前后各 2 页挂载画布。最多 2 个阅读/后台栅格化任务并发，优先当前页和滚动方向。
- 先低清显示，空闲 600 ms 后提升当前页清晰度；最大 DPR 1.5、高清画布最大 4 MP、低清最大 1.2 MP。离开范围取消任务并释放画布；关闭或切文档销毁 loadingTask、worker、请求、监听器和会话令牌。
- 页码输入、前后翻页、缩放、适应宽度、内置目录和页面重试。混合尺寸使用测量后的占位几何并保持滚动锚点。

### OCR、缓存与 AI

- 低优先级单页分析队列，先读取文字，扫描页以长边 1568 像素独立渲染后调用原生离线 OCR。阅读队列忙时延后后台处理，原生推理线程限制为 2。
- 按文档指纹、页码、语言和引擎版本持久缓存；OCR 框的阅读器内存缓存最多 12 页，共享缓存最多 48 页。扫描空白页也可保存；失败不会伪装成成功。
- 本地文字索引最多保留最近 3 个文档。`pdfIndex.list/search` 只搜索已完成页面，按关键词命中比例排序；不提供语义向量检索。原始全文索引重启后随按页缓存读取逐步恢复。
- OCR 需要启用已有插件并具备模型，不自动上传本地文档。暂停不打断已经进入原生推理的一页。

## 测量方法

```powershell
npm run test:pdf -- 'D:\BaiduNetdiskDownload\实验心理学  第9版_坎特威茨.pdf' "$env:APPDATA\unyra\ocr-models"
```

脚本使用真实 Electron、正式 CSP、真实协议和离线 OCR，挂载正式 `PdfDocView`，使用独立临时 profile。测试包含首次会话、销毁并重建 renderer 后的缓存复用、跳转 2/500/686 页、两轮远跳压力、内置目录 fixture、切文档后旧令牌失效。不会改真实用户的设置或缓存。

首屏从创建测试 BrowserWindow 开始计时，到第一页画布真正绘制完毕；同时检查暗色像素，避免把空白画布算成功。这包括 fixture 导航和阅读器初始化，**不是安装包全应用的端到端打开时间，也不是清空操作系统磁盘缓存后的冷启动**。第二次会话重新创建 PDF worker，但复用磁盘 OCR 缓存。页码跳转按提交页码到目标画布完成低清绘制计时。

### 功能与内存

- 真实扫描封面有 6,763 个暗色采样点，已人工检查截图，避免把空白画布算作首屏成功。
- 远跳后第 1 页画布释放，当前页为 686，位置误差在验收允许范围内。两轮 100/200/300/400/500/600/686 跳转，最大显示画布为 6。
- 首次会话渲染进程 private bytes 在跳转压力前、第一轮后、第二轮后分别为 385,260 / 438,416 / 359,728 KiB；工作集为 411,652 / 544,000 / 515,672 KiB，峰值 579,496 KiB。私有内存未随两轮浏览持续上涨，但总工作集会波动；这些短测不能证明长期内存完全不增长。
- 离线 OCR 在阅读期间识别封面及当前页，搜索可在全书完成前命中“实验”。重建 renderer 后，第 1 页命中磁盘缓存，没有再次 OCR；新调用识别的是第 2 页。验收未等待全部 686 页完成。
- 三页混合尺寸 fixture 的命名目录跳转到第 3 页，并聚焦正确页面。切文档后旧画布释放，旧能力 URL 返回 403。样本没有内置目录，因此没有将它用于书签跳转验收。

## 限制与后续

1. 任意远跳仍可能需要遍历未缓存的页树节点和解码扫描图像；没有将一秒内任意跳页作为已完成承诺。后续可研究持久页定位索引、解码缓存和原生引擎对比。
2. 仅对样本及自动生成的目录/混合页树 fixture 验证；不代表加密、损坏、特殊字体、超大单页等所有 PDF 已覆盖。未配置标准字体与 CMap 的部分 CJK 文档可能缺字，保留系统阅读器入口。
3. 后台 OCR 会继续读取和解析后续页面；初始快速预览不代表完整 686 页已识别。已完成文字按页可用，不包含复杂表格结构和全书摘要。
4. 有界画布和 OCR 框缓存不等于整个进程恒定内存。PDF.js 会保留已读取字节、页树和字体等数据，Chromium 也保留缓存。短时压力结果不能证明数小时使用完全不增长。
5. 自定义 worker 补丁与固定引擎版本耦合，升级依赖须运行兼容测试、混合页树测试和样本验收。
