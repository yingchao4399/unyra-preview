# 无限画布学习应用设计报告

**设计目标：** 在归一的对象化学习思想基础上，设计一个“画布负责组织，聚焦区负责学习，系统负责复习”的产品。

## 1. 产品定义

### 产品承诺

用户可以从一个问题或一组资料开始，在一张不断成长的知识画布上建立自己的理解；每张卡片都有来源、关系、学习状态和下一次回忆任务。

### 设计原则

1. **先有内容，再有结构。** 不要求用户开局设计完整课程。
2. **候选关系必须可确认。** AI 生成的是建议，不是事实。
3. **全图用于导航，聚焦区用于学习。** 同一时间只突出一个学习动作。
4. **每个重要结论都能回到证据。** 资料、原文、版本和推断要分开。
5. **学习状态来自行为。** 不用“看过”推断“掌握”。
6. **画布操作要产生认知收益。** 拖拽、连线、分组都应服务于理解。

## 2. 信息架构与对象模型

### 2.1 一级对象

| 对象 | 必要字段 | 说明 |
|---|---|---|
| Space | id, title, goal, createdAt | 一个学习主题或研究项目 |
| Source | id, type, uri, excerpt, version | PDF、网页、视频、文本或用户输入 |
| Card | id, type, title, body, status | 概念、问题、例子、结论、任务、来源 |
| Relation | from, to, type, rationale, evidence[] | 前置、组成、因果、对比、例证、支持或质疑 |
| Practice | id, cardIds, prompt, answer, rubric | 一次回忆或应用任务 |
| MemoryState | cardId, confidence, lastSeen, nextReview | 基于行为估计的记忆状态 |
| Session | startedAt, activeCard, actions | 学习会话和行为事件 |

### 2.2 卡片类型

- **问题卡：** 我想弄懂什么。
- **概念卡：** 一个可独立解释的概念。
- **来源卡：** 原文、截图、数据或链接。
- **例子卡：** 具体案例、代码、反例。
- **结论卡：** 用户确认过的总结。
- **练习卡：** 需要回忆、判断或应用的任务。
- **任务卡：** 下一步要完成的学习动作。

不要一开始把所有东西都建成“知识节点”。卡片类型让用户知道它为何存在，也让 AI 能选择合适的学习动作。

## 3. 画布的三种模式

### 3.1 路线模式

回答“从哪里开始、下一步是什么”。只显示目标、阶段和必要前置关系；支持折叠和完成状态。它接近归一的大纲，但不承载所有笔记和来源。

### 3.2 概念模式

回答“哪些概念互相支持、冲突或依赖”。显示关系类型、证据数量和待验证状态。支持从一张卡片展开一跳或两跳邻居。

### 3.3 工作台模式

回答“我现在如何组织这批材料”。支持自由摆放、分组、临时便签和草图；临时元素可以稍后转成正式卡片或直接归档。

三种模式共享卡片，但默认不共享所有边。这样可以避免一条“视觉分组线”被误当成学科依赖。

## 4. 核心用户流程

### 首次使用

1. 输入问题或拖入资料。
2. 系统显示 3–5 张候选卡片和候选关系。
3. 用户一键确认、删除或改写。
4. 进入聚焦区，先回答一个低难度问题。
5. AI 根据回答补充讲解，并把关键结论写回卡片。
6. 生成 1–3 个短练习，完成后给出下一步建议。

### 日常学习

1. 首页显示“今天要回忆的卡片”和“上次未解决的问题”。
2. 点击卡片进入聚焦区，而不是直接打开整张大图。
3. 先隐藏答案，让用户口述、输入或拖关系。
4. AI 根据证据反馈，记录错误类型和信心。
5. 练习结束后回到画布，显示知识状态变化。

### 深入学习

选中文本或卡片后，提供：解释、建立前置卡、找来源、反例、生成练习、写个人理解六个动作。每个动作都说明会创建或修改什么对象。

## 5. 关键界面设计

### 5.1 桌面端布局

```text
┌──────────────┬──────────────────────────────┬──────────────┐
│ 空间 / 今日  │          无限画布             │ 聚焦学习区    │
│ 复习 / 来源  │  卡片、关系、证据、缩略图     │ 问题、回答、反馈│
│              │  画布模式切换、筛选、定位     │ 来源、下一步    │
└──────────────┴──────────────────────────────┴──────────────┘
```

默认宽度建议 220 / 自适应 / 360；聚焦区可以收起。画布顶部固定“当前模式、筛选、回到当前卡片、适应画布”，避免把这些动作藏在右下角。

### 5.2 卡片最小信息

卡片首屏只显示：类型、标题、用户状态、关系数、来源数、下一次复习时间。正文在聚焦区展开。卡片颜色表达类型或状态之一，不要同时用颜色表达分支、难度和来源。

### 5.3 关系交互

拖出连线后先选择关系类型，再要求输入一句“为什么这样连”。如果 AI 生成关系，连线显示“建议”标记，用户确认后变成正式关系。点击关系可查看来源和反例。

## 6. AI 设计

### AI 的五个角色

1. **整理者：** 从资料中提取候选卡片和关系。
2. **导师：** 在聚焦区解释、类比、举例和追问。
3. **质疑者：** 找冲突、边界条件和证据不足。
4. **出题者：** 生成回忆、判断、应用和迁移练习。
5. **教练：** 根据历史错误安排下一步，而不是不断生成新内容。

### AI 输出规则

- 默认写入草稿区，用户确认后才修改正式卡片。
- 每个事实性结论尽量附来源片段或标记“模型推断”。
- 不自动把一条聊天消息拆成大量卡片；先给候选集合。
- 任何“已掌握”状态必须由练习行为触发。
- 生成关系时同时生成反例或“不成立的条件”。

## 7. 学习状态与练习系统

### 掌握度

不采用单一的 learning / mastered。建议使用四个维度：

- **理解：** 能否用自己的话解释。
- **辨认：** 能否在选项或例子中识别。
- **应用：** 能否在新问题中使用。
- **迁移：** 能否连接到另一个主题或反例。

每个维度取 0–3 级，卡片状态由练习结果和用户自评共同更新。

### 练习类型

- 自由回忆：隐藏正文，写出定义或步骤。
- 关系回忆：补全缺失的连线或关系类型。
- 解释审查：用户先解释，AI 按 rubric 反馈。
- 例题应用：把概念用于新案例。
- 反例判断：判断某例子为何不满足定义。
- 混合复习：跨相邻主题抽取问题，避免只在原位置记忆。

## 8. MVP 范围

### P0（必须验证）

- 导入文本 / PDF / 网页并保存来源。
- AI 生成候选卡片，用户确认后上画布。
- 自由拖拽、缩放、分组、关系类型和关系说明。
- 聚焦学习区：解释 → 用户回答 → AI 反馈。
- 3 种练习：自由回忆、关系补全、应用题。
- 复习队列、卡片状态、来源回跳、撤销和本地导出。

### P1（形成差异）

- 选词建卡、引用片段和版本历史。
- AI 质疑者、反例生成、关系置信度。
- 间隔复习调度、错误分类和跨主题混合复习。
- 路线 / 概念 / 工作台模式切换。

### P2（规模化）

- 多设备同步与端到端加密。
- 协作白板、教师模板和课程发布。
- 插件、视频时间轴、代码沙箱、语音和移动端。

## 9. 技术架构建议

- **前端：** React + TypeScript；画布渲染层与业务状态分离。
- **画布：** 使用稳定的节点/边模型和视口变换；大量卡片时采用视口裁剪、分层渲染和缩略图缓存。
- **数据：** 事件日志 + 当前快照；卡片、关系、来源、练习和记忆状态分别建模。
- **本地存储：** Markdown/JSON 可导出，二进制来源进内容寻址目录；敏感字段加密。
- **AI：** 统一 provider 接口，提示词、工具调用、证据和模型版本写入运行记录。
- **同步：** 先做可导出的单机版本，再做基于变更集的同步；不要一开始把本地文件和云数据库双写。

## 10. 成功指标

### 学习结果

- 一周后回忆正确率。
- 解释任务的 rubric 得分。
- 应用题从“看答案”到“独立完成”的转化率。
- 错误再次出现的间隔和修复率。

### 产品行为

- 从导入到第一次有效练习的时间。
- 首次会话完成的卡片确认率。
- 卡片被回忆的比例，而不是只被打开的比例。
- AI 候选关系被用户保留、修改和删除的比例。
- 七日和三十日复习回访率。

### 质量与信任

- 用户查看来源的比例。
- 关系被标记“待验证”的比例。
- AI 生成内容被用户纠正的比例。
- 数据导出成功率和恢复成功率。

## 11. 风险与防护

| 风险 | 防护 |
|---|---|
| 画布越大越混乱 | 默认局部视图、聚焦模式、路径筛选和折叠 |
| AI 生成错误结构 | 候选关系、来源证据、置信度、用户确认 |
| 用户只整理不学习 | 每个主题必须有待回忆任务；首页优先显示复习 |
| 用户被功能吓退 | 从资料或问题开始，逐步揭示对象模型 |
| 本地数据丢失 | 自动快照、可读导出、备份提醒和恢复演练 |
| 模型成本失控 | 小模型做提取与分类，大模型只做解释、质疑和复杂练习 |

## 12. 最终设计判断

新产品应把“无限画布”从一个视图升级为三种明确的学习模式，把“AI 生成”从自动写入升级为候选和证据，把“考试”从终点升级为日常检索，把“节点”从抽象知识单元升级为有来源、有关系、有练习的学习对象。这样才能既吸收归一的精华，又避开它在复杂度、信任和学习闭环上的问题。
